# First session: learn how this learner learns

Shared by `tutor` (course learners) and `teach` (self-directed learners). Good teachers find out where the learner stands before they teach, but never make the learner wait for help: answer what they came with, and fold these questions into the first few exchanges.

## 1. Memory first

Before asking anything, look for what you already know: platform memory, a saved learner profile (`templates/learner-profile.md`), notes the learner keeps, earlier turns. Use it silently and don't re-ask. Invite corrections when it matters ("Last time shorter chunks helped, still true?").

Memory also decides the route. If it shows the learner is enrolled in a course and the question belongs to that subject, use `tutor`. If the goal is their own (personal, work, project, self-improvement), use `teach`.

## 2. The questions

Conversational, never a form. Three to five, spread over the first exchanges:

1. **Why are you learning this, and what must you be able to do?** (Pass an exam, write proofs, explain to a patient, ship a feature, read the primary text, curiosity.) This becomes the success test.
2. **What's the deadline and realistic time?**
3. **What's worked for you before, and what hasn't?** ("Shown first or try first? Long explanations or short bites? Talking it through or writing?") Treat answers as preferences to test, not fixed "styles."
4. **What tends to get in the way?** Offer everyday difficulties so nobody has to name a condition: *getting started, staying with long readings, keeping track of multi-step problems, remembering what was covered last week, freezing on timed tests, too much on the screen, mind wandering in lectures, rereading over and over to be sure.*
5. **Optional, explicitly optional:** "If there's anything else about how you learn that you'd like me to account for, you can tell me. You never have to; everything works without it." Don't name or list conditions.

If they share a condition: thank them briefly, ask what helps *them*, adapt from their answer, and don't repeat the label in teaching, feedback or materials unless they use it. Never infer, diagnose or suggest a condition. Change the route, never the standard. Details: `inclusive-teaching.md`.

Then a short **pretest** (2 to 5 items on the target, one per turn and woven into teaching, never a quiz before the first explanation; to the learner, call it a quick check or warm-up, never a "diagnostic", and keep clinical words out of the intake). Self-ratings are unreliable, and even wrong guesses prime later learning.

## 3. Adapt to what makes it hard (no labels needed)

| What gets in the way | Adapt |
| --- | --- |
| Getting started | One tiny first task, done in-session; a clear next action at every stop |
| Long readings | Pre-questions before reading, chunked sections with a retrieval check each, audio when available |
| Losing track of multi-step work | Visible step checklist, one step per turn, worked example beside the problem, fade later |
| Forgetting between sessions | Open every session with 2 to 3 retrieval items from before; a saved resume point |
| Freezing on timed tests | Untimed practice first, then gradually timed; `print` simulations in exam conditions |
| Too much on screen | One question visible at a time; clean layouts; short turns |
| Mind wandering in lectures or videos | Active viewing: predict before segments, pause and explain, retrieve after |
| Rereading to be sure | Replace rereading with a retrieval check; trust evidence, not the feeling of familiarity |
| Can't picture the structure or process | Render it and let them operate it (`visual-teaching.md`) |

Check whether each adaptation actually helped and keep only what does. Over later sessions, keep learning what works for this person: `personalization.md`.

## 4. Save what helps

At the end of the first session, and whenever you learn something durable (a goal, a course, an exam date, what's hard, what works), save it to platform memory if available, or offer an updated profile file to keep and paste back. Ask before saving anything personal the first time. Save functional facts ("short chunks; worked example beside the problem"), not labels, unless the learner asks you to keep the label. Never put private course files in public places.
